# LongLive2.0 昇腾稀疏注意力性能分析

## 1. 报告范围

本文分析 LongLive2.0-5B 基础权重在昇腾 NPU 上采用 `dense`、`hsa_cag`、`sla_cag` 和 `hsa_sla_cag` 四种注意力路径时的无 profiler 推理性能。报告只使用同一基础 checkpoint：

```text
/mnt/share/r50063443/LongLive/checkpoints/longlive2_5b/longlive2_merged_generator.pt
```

原始 run 使用的是部署机上的 LongLive2.0 合并 Generator；本文仅记录文件名和用途，不固化个人服务器绝对路径。

数据来自 2026-08-12 的四组 benchmark suite，覆盖 SP1/SP4、5/32/64 秒和 `dit_only`/`async_vae`。每个 case 均包含 3 次有效测量；本文以 p50 作为正式延迟指标，以 mean、p95 和异步流水线分解作为辅助证据。

| 报告元数据 | 值 |
| --- | --- |
| 数据日期 | 2026-08-12 |
| 仓库分支 | `feat/unified-sparse-attention` |
| 整理时提交 | `67145af` |
| 数据类型 | 无 profiler benchmark 汇总 |
| 报告状态 | 基础权重阶段性分析 |

本文回答三个问题：

1. 稀疏注意力能否在 DiT 整网而非仅算子微基准上降低延迟？
2. 稀疏收益在 SP1 和 SP4 下是否一致？
3. DiT 收益能否转化为包含异步 VAE 的端到端收益？

## 2. 实验条件与可比性

| 项目 | 设置 |
| --- | --- |

| pixel 帧数 | 125 / 765 / 1533 |

Dense 与 sparse case 的 checkpoint、时长、采样设置、SP/DP 和 VAE 模式均匹配，汇总中的 `checkpoint_matched_to_dense=True`。因此同一 SP、时长和 VAE 模式内的延迟可直接比较。

## 3. 指标与计算方法

本文重新根据 p50 计算加速比，不直接使用原始汇总中基于 mean 的 `dense_speedup`：

```text
p50 加速比 = dense generation_seconds_p50 / sparse generation_seconds_p50
延迟降低量 = dense p50 - sparse p50
延迟降低率 = (dense p50 - sparse p50) / dense p50 × 100%
SP4 扩展倍数 = SP1 p50 / SP4 p50
SP4 并行效率 = SP4 扩展倍数 / 4 × 100%
```

表格中的红色粗体表示当前对比中最重要的正向结果或明确的性能退化。

派生指标使用用户提供的原始精度计算，正文延迟保留 3 位小数，百分比保留 2 位，加速比保留 3 位；显示值的再次手工计算可能产生不超过末位舍入误差的差异。

## 7. 异步 VAE 端到端结果

### 7.1 p50 原始值与派生加速比

| SP | 时长 | dense p50 s | HSA p50 / 加速比 | Hybrid p50 / 加速比 | SLA p50 / 加速比 |
| --- | --- | ---: | ---: | ---: | ---: |
| SP1 | 5s | 23.304 | 22.833 / 1.021x | **22.822 / 1.021x** | 22.890 / 1.018x |
| SP1 | 32s | 138.555 | **120.053 / 1.154x** | 122.264 / 1.133x | 121.757 / 1.138x |
| SP1 | 64s | 280.811 | 238.627 / 1.177x | **236.810 / 1.186x** | 237.568 / 1.182x |
| SP4 | 5s | **21.004** | 21.334 / 0.985x | 21.528 / 0.976x | 21.389 / 0.982x |
| SP4 | 32s | **119.962** | 124.013 / 0.967x | 120.728 / 0.994x | 120.533 / 0.995x |
| SP4 | 64s | **239.501** | 239.654 / 0.999x | 240.105 / 0.997x | 241.495 / 0.992x |

SP1 的 32/64 秒仍能保留约 1.13x–1.19x 端到端收益，因为 DiT 本身比 VAE 慢或与其接近。SP4 把 DiT 压缩后，所有 sparse case 的端到端加速比均不超过 1，<span style="color:#c00000"><strong>说明端到端关键路径已从 DiT 转移到单卡 VAE 和流水线 drain</strong></span>。

### 7.2 SP4 异步流水线原始 mean 分解

以下字段均为 3 次测量的 mean，因此用于机制归因，不与上一表的 p50 混算。

| 时长 | 方法 | generation s | AR loop s | VAE decode s | enqueue s | drain s | overlap s | queue peak |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 32s | dense | 120.054 | 104.640 | 114.557 | 57.282 | 11.360 | 103.197 | 2.00 |
| 32s | hsa_cag | 123.497 | 58.584 | 116.729 | 19.376 | 59.677 | 57.052 | 12.33 |
| 32s | hsa_sla_cag | 121.511 | 57.384 | 116.159 | 19.642 | 60.246 | 55.913 | 12.33 |
| 32s | sla_cag | 121.775 | **57.284** | 116.044 | 20.350 | **60.241** | 55.803 | **12.33** |
| 64s | dense | 241.419 | 219.532 | 229.463 | 123.448 | 11.369 | 218.094 | 2.00 |
| 64s | hsa_cag | 240.230 | 114.780 | 230.866 | 36.242 | 117.594 | 113.272 | 24.33 |
| 64s | hsa_sla_cag | 240.759 | 114.719 | 230.868 | 38.667 | 117.642 | 113.226 | 24.33 |
| 64s | sla_cag | 241.125 | **114.614** | 230.719 | 40.978 | <span style="color:#c00000"><strong>117.606</strong></span> | 113.114 | <span style="color:#c00000"><strong>24.33</strong></span> |

SP4 sparse 在 64 秒时将 AR loop 从 dense 的 219.5 秒降至约 114.6 秒，但 VAE decode 仍约 230.7 秒；48 个 VAE chunk 的 queue peak 达到约 24.3，末尾仍需约 117.6 秒 drain。该证据支持“VAE 消费速度低于 sparse DiT 生产速度”的解释。

`ar_loop_seconds` 在异步模式中包含 enqueue 等待和队列背压，不能作为纯 DiT 延迟；纯 DiT 结论必须使用第 4–5 节的 `dit_only generation_seconds_p50`。

## 8. 显存分析

| 模式 | SP | 时长 | dense 峰值 GiB | sparse 范围 GiB | VAE 峰值 GiB |
| --- | --- | ---: | ---: | ---: | ---: |
| dit_only | SP1 | 5/32/64s | 40.59 / 44.85 / 49.91 | 40.64–49.97 | 不适用 |
| dit_only | SP4 | 5/32/64s | 26.03 / 30.26 / 35.35 | 26.04–35.37 | 不适用 |
| async_vae | SP1 | 5/32/64s | 40.58 / 44.79 / 49.78 | 40.63–49.85 | 11.39 |
| async_vae | SP4 | 5/32/64s | 26.02 / 30.20 / 35.23 | 26.03–35.25 | 11.40–11.45 |

稀疏方法没有显著降低峰值显存。这与实现一致：稀疏 softmax 只计算选中 KV blocks，但系统仍维护完整的 32 latent 帧滚动 KV cache；SLA/Hybrid 的路由和线性补偿也会读取完整 KV 统计量。

## 9. 结论

1. **整网有效性**：三种稀疏方法在全部 DiT-only case 上均快于 dense，证明收益不是仅存在于算子微基准。
2. **最佳纯性能方法**：SLA+CAG 在所有 DiT-only case 中延迟最低。最强结果为 <span style="color:#c00000"><strong>SP1、64 秒、p50 1.601x，延迟降低 37.54%</strong></span>；SP4、64 秒为 <span style="color:#c00000"><strong>1.311x，降低 23.74%</strong></span>。
3. **Hybrid 额外成本**：HSA+SLA+CAG 比 SLA 慢约 1.35%–3.42%，其 HSA 预筛选是否值得需由质量收益决定。
4. **SP 影响**：SP4 降低绝对延迟，但同时降低稀疏的相对加速比；这是通信和固定成本占比升高的结果。
5. **端到端瓶颈**：SP4 + async VAE 下 sparse 端到端加速比约 0.97x–1.00x。当前继续优化 attention 不能显著降低完整视频延迟，必须提高 VAE 吞吐或增加 VAE 并行度。
6. **显存边界**：当前稀疏是计算稀疏而非 KV 存储压缩，不能宣称具有显著显存收益。

## 10. 科研有效性与限制

- 每个 case 只有 3 次有效测量，原始输入仅提供 mean/p50/p95，没有逐次 latency，无法独立复算标准差、置信区间或显著性检验。
- `n=3` 时 p95 很不稳定，正式结论以 p50 为主。
- SP1 与 SP4 使用不同数量的 DiT NPU；扩展倍数衡量单视频延迟，不代表单位算力效率或成本收益。
- HSA 使用 `0.85/0.95` CAG 目标/基准稀疏率，SLA/Hybrid 使用 `0.90/0.93`，方法间不是相同实际稀疏率的纯算法消融。
- 异步流水线字段存在重叠，不能将 AR、VAE、enqueue、drain 简单相加。
- 本报告仅覆盖基础权重；训练后权重需要重新执行相同矩阵，不能直接沿用本报告的加速比。
